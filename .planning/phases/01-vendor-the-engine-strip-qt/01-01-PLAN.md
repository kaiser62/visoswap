<measured_facts>
These were measured, not assumed. Do not re-derive them; build against them.

**Test interpreter.** `D:/Visomaster/dependencies/Python/python.exe` is CPython 3.10.13 and has
every runtime dependency the engine needs — torch 2.4.1+cu124, torchvision 0.19.1+cu124, kornia
0.8.0, onnxruntime 1.20.0, tensorrt 10.6.0, cv2 4.10.0, skimage 0.21.0, numexpr, ftfy, regex, onnx
— **and it also has PySide6 6.7.2 installed.** That last fact is a feature, not a problem: it makes
the block-and-import probe do real work. Proving vendored code cannot reach Qt on an interpreter
where Qt *is installed* is a strictly stronger result than proving it on one where Qt is absent.

**The repo's default interpreter cannot run this test.** `D:/Dev/Miniconda3/python.exe` (3.13.13)
is missing torch, torchvision, kornia and tensorrt. A probe run there fails on `import torch`,
which must never be reported as a Qt-cleanliness pass.

**Blocking `PySide6` alone is not sufficient.** Measured: with only `PySide6` blocked,
`app/processors/workers/frame_worker.py` fails with `QtBindingsNotFoundError: No Qt bindings could
be found` — an error type raised by `qtpy`, not by the block. The transitive chain out of the two
`app/ui` action modules reaches Qt through `qtpy` as well as directly. The gate must therefore
block every Qt binding root, not just one.

**Baseline, measured with the Qt roots blocked against the unmodified VisoMaster source:**
8 of 10 probed modules already import clean — `utils.faceutil`, `models_data`, `face_detectors`,
`face_masks`, `face_editors`, `face_swappers`, `utils.dfm_model`, `external.clipseg`. Only
`workers/frame_worker.py` and `models_processor.py` fail. That is the work of plans 03 and 04.

**GPLv3 text is available locally** at `D:/Visomaster/LICENSE` (34.3 KB, "GNU GENERAL PUBLIC
LICENSE / Version 3, 29 June 2007"). Copy it; do not fetch it over the network and do not retype it.

Vendor exactly one file: copy `D:/Visomaster/app/processors/utils/faceutil.py` (2,389 lines) byte

rewriting — which is precisely why it is the tracer: it isolates the harness from the rewrite.

Create `tests/_qt_guard_probe.py`, a standalone script run as a subprocess, never imported by
pytest. It must:
  - define the blocked roots as `PySide6`, `PySide2`, `PyQt5`, `PyQt6`, `qtpy`, `shiboken6`,
    `shiboken2` — all of them, for the measured reason that the transitive chain reaches Qt via
    `qtpy` and not only via a direct binding import;
  - install a `sys.meta_path` finder at index 0 whose `find_spec` raises `ImportError` naming the
    offending module when the root package of the requested name is in that set, and returns `None`
    otherwise;
  - prepend the repo root to `sys.path` so `visoswap` resolves without an install step;
  - import each module named in `sys.argv[1:]`;
  - distinguish failure modes by exit code, because conflating them is how this gate goes green for
    the wrong reason: exit `1` printing `QT_REACHED:<module>:<detail>` when the block trips or when
    any blocked root is present in `sys.modules` after all imports succeed; exit `2` printing
    `DEPS_MISSING:<module>:<missing>` when a `ModuleNotFoundError` names a root that is *not* in
    the blocked set; exit `3` printing `IMPORT_ERROR:<module>:<detail>` for anything else; exit `0`
    printing `CLEAN` only when every module imported and no blocked root is in `sys.modules`.

Create `tests/conftest.py` exposing an `engine_python` fixture that resolves the interpreter per
this task's precondition and a helper that runs the probe against a list of module names, returning
`(exit_code, stdout)`.

Create `tests/test_qt_free.py` with two tests. First, `test_engine_python_has_runtime_deps`, which
asserts the resolved interpreter imports torch — so a missing dependency fails loudly and
attributably instead of being mistaken for a Qt problem. Second,
`test_vendored_module_imports_without_qt`, which runs the probe against
`visoswap.processors.utils.faceutil` and asserts exit code `0`. On exit `2` the assertion message
must name the missing dependency and the resolved interpreter path. There is no `skip` path in
either test: a skip here is a false green on the one criterion this phase exists to prove.
