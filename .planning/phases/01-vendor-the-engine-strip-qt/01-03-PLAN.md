`grep -on "main_window\.[a-zA-Z_][a-zA-Z0-9_]*"` per file, then union the attribute names, gives
you the list plus the line evidence in one pass. Keep the per-file breakdown; the union alone
loses the information about which attributes die with `video_processor.py`.

the design's stated count. Per file:

  - `workers/frame_worker.py` (7): `control`, `editFacesButton`, `models_processor`, `parameters`,

  - `video_processor.py` (6): `control`, `display_messagebox_signal`, `loading_new_media`,

If your enumeration disagrees with this, your enumeration wins — the source is authoritative and
these numbers are a checksum, not an input. But say so loudly in the doc and in the SUMMARY,
because a disagreement means the design's coupling analysis is stale and Phase 2 needs to know.

Write `01-CONTEXT-SURFACE.md` into the phase directory as a table: attribute, which files read it,
line numbers, what it holds, and a verdict of **kept** or **dropped** with a one-line reason.
Expected verdicts:

  Kept (7). `control` — the global-tier settings dict, Phase 3's global tier. `parameters` — the
  project-tier settings dict, Phase 3's project tier. `target_faces` — the detected-face store.
  `models_processor` — the engine's own model registry. `dfm_models_data` — DFM model metadata,
  read at `models_processor.py:159`. Plus two booleans replacing the button reads:
  `swap_faces_enabled` for `swapfacesButton.isChecked()` and `edit_faces_enabled` for
  `editFacesButton.isChecked()`, which are read as plain booleans at four sites in
  `frame_worker.py` and nowhere else.

  Dropped (8). `video_processor` — the Qt playback loop, dropped whole; the scheduler owns
  playback. `model_load_dialog`, `model_loaded_signal`, `model_loading_signal`,
  `display_messagebox_signal` — Qt progress and message-box notification with no consumer on the
  swap path. `loading_new_media`, `processed_frames`, `videoSeekSlider` — read only by
  `video_processor.py`, so they die with it.

Add two short notes to the doc, both of which are load-bearing for later phases and easy to lose:

  1. The eight dropped attributes include the only model-load progress signalling the engine had.
     Nothing on the swap path consumed it, so it goes. If Phase 4 wants load progress for a 12 GB
     weight set, it adds a Qt-free callback to `EngineContext` — record that as the re-add path so
     it reads as a decision rather than an omission.
  2. `dfm_models_data` is populated upstream by `get_dfm_models_data()` in
     `app/helpers/miscellaneous.py`, which plan 02 deliberately did not vendor. `EngineContext`
     carries the dict; who fills it is Phase 2's call. Flag it so Phase 2 does not find an empty
     dict and treat it as a bug in this phase.

Write `tests/test_context_surface.py` asserting `EngineContext` has exactly the seven expected
field names — no more, no fewer — by reading `dataclasses.fields()`. It pins the contract that
Phase 2 and Phase 3 build against, and it fails loudly if someone quietly widens the surface back
toward a god object.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller -> `EngineContext` | The single object through which all settings, target faces and flags enter the engine. It replaces a god object; if it grows back into one, the boundary stops being a boundary. |
| `EngineContext.control` / `.parameters` -> inference | Untyped dicts whose values reach model selection and file-path construction. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-09 | Elevation of privilege | `EngineContext` field surface | medium | mitigate | An open-ended context is how the god object returns, and with it the hidden-state problem PROJECT.md exists to fix. `tests/test_context_surface.py` asserts exactly seven fields, so widening it is a deliberate, reviewed edit. |
| T-01-10 | Tampering | `context.control['MaxDFMModelsSlider']` and model-name keys | medium | accept | Settings values are untyped dicts here and reach model-registry lookups. Typing and validation is SCHEMA-01's job in Phase 3; adding ad-hoc validation now would be superseded and would fight the generated schema. Accepted for Phase 1, where nothing executes these paths. |
| T-01-11 | Repudiation | Deleted model-load progress signalling | low | accept | Removing the only load-progress notification without a record makes a future regression look like a bug. Mitigated by documenting the drop and its re-add path in `01-CONTEXT-SURFACE.md` rather than leaving a silent no-op stub. |
| T-01-12 | Tampering | npm/pip/cargo installs | high | accept | This plan performs no package-manager install. |
</threat_model>
