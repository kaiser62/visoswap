<measured_facts>
Measured during planning. Plan against these; do not re-derive.

**The deferred deserialization call is at `visoswap/processors/external/clipseg.py` line 305**, and
its upstream twin is line 300 — the five-line attribution header shifts every vendored line by five.
It loads a shift vector from a file resolved relative to the module. Two facts about it that change
how the task should be framed, neither of which was known when Phase 1 deferred it:

- It sits inside a branch guarded by a `fix_shift` constructor argument that **defaults to false**,
  and the only construction site in the codebase — `face_masks.run_CLIPs` — does not pass it. The
  call is therefore dead on the live path today. Harden it anyway: it is one keyword argument, the
  guard is one constructor argument away from being flipped by a future caller, and a dead unsafe
  deserializer is still an unsafe deserializer sitting in the tree.
- The file it references does not exist in the repository, so if the branch were ever taken the call
  would raise a missing-file error before reaching the deserializer. Do not "fix" that by adding the
  file. Do not delete the branch either — the vendored copy must keep diffing cleanly against
  upstream, and a one-keyword change is the smallest possible diff.

**The one live deserialization call is already hardened.** `visoswap/processors/face_masks.py` line
256 loads the CLIPseg refined weights and already passes the safe-loading keyword, inherited
verbatim from upstream. The scan must therefore find at least two call sites, not one, or it is
scanning the wrong tree.

**LivePortrait weights are present in full.** `model_assets/liveportrait_onnx/` holds
`motion_extractor.onnx` (107 MB), `appearance_feature_extractor.onnx`, `warping_spade-fix.onnx`
(402 MB), `warping_spade.onnx`, `stitching.onnx`, `stitching_eye.onnx`, `stitching_lip.onnx` and
`lip_array.pkl` (658 bytes). Nothing needs downloading. This is what makes LivePortrait the one of
the three risk paths that is runnable today.

**`FaceEditors.__init__` opens the lip array and swallows a missing file**, leaving the lip array as
nothing. Because the constructor runs when the models processor is constructed, a wrong working
directory produces a fully-constructed engine with a silently disabled lip retarget rather than an
error. Assert the array is populated.

**The TensorRT plugin is not needed.** The warping-spade path loads a platform-specific plugin
library only when the provider is TensorRT-Engine. Plan 02-02 selected CUDA, so the ONNX path is
taken and the plugin is never touched. The motion extractor's TensorRT branch is guarded by a
comparison that upstream disabled with a leading marker character, so that branch is unreachable
regardless of provider — worth knowing before reading the file and concluding the provider choice
is broken.

**The editor path is gated on `edit_faces_enabled` on the context object**, read at three sites in
the frame worker, and on the per-face `FaceEditorEnableToggle` project-tier key read at the top of
the editor routine. Both must be on. The editor type key defaults to the human-face model and is
read at eleven sites inside the editor routine.
</measured_facts>
