Write `backend/services/engine_backend.py`: `EngineFrameGenerator`, a `FrameGenerator` subclass over
`visoswap.engine.Engine`. This is the file that replaces 922 lines of hidden-Qt-window driving, and
it should be a fraction of that size — the reduction is the point, not a coincidence.

Import `visoswap.engine` **lazily**, inside the methods that need it, not at module scope. The
reference does the same thing at `generator.py:344` for the same reason: `backend.config` and
`backend.api` must stay importable on an interpreter with no torch, or every test that only wants a
route becomes a test that needs a CUDA stack.

Map the seam onto the engine's three published methods and nothing else. `bind` calls `load` and
`detect_faces` and holds the result — this is the whole reason the in-process path costs 0.064s a
frame instead of 0.886s, and the reference's own docstring says so. `generate_at` calls `swap` for
the frame number the timestamp resolves to and encodes the returned `ndarray` to the configured
generated format. `unbind` and `close` release what `bind` took.

Frame number from timestamp is a correctness question, not a rounding detail. `CLAUDE.md` invariant
1 says target timestamps are deterministic and compared with tolerance, never equality, and
invariant 2 says frame selection is nearest-previous. Derive the frame number from the timestamp and
the media's own frame rate, floor rather than round, and say in the docstring which invariant that
serves. Rounding up can select a frame that does not exist at the end of a clip, and rounding to
nearest can select a future frame, which invariant 2 forbids outright.

Settings come from the Phase 3 store, not from a new dictionary. `Engine.swap` takes a settings
mapping; `visoswap.settings.store.resolve_parameters` returns the project tier with all 168 keys
present and typed, which is the shape `frame_worker` indexes by face id. Call it. Plan 04-05 widens
this to the face tier and the endpoints; here it is the project tier and one face, because a tracer
proves the path rather than the breadth.

Wire the adapter into `services/generator.py`'s factory so the single remaining backend value
selects it. Nothing else in `generator.py` changes.

explicitly: `load` before `detect_faces`, both before any `swap`. A tracer that swaps before loading
