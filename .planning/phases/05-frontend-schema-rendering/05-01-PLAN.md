Backend half of the FRONTEND-01 vertical slice: the three read endpoints of D-05 — GET /api/schema, GET /api/projects/{project_id}/settings, GET /api/presets — wrapping the Phase 3 store, plus the read-API contract tests.

Purpose: Prove the riskiest layer of this phase first: the Phase 3 settings store is synchronous sqlite3 while the Phase 4 backend is async aiosqlite, and nothing yet applies the settings DDL or seeds presets in the backend database. A tracer here retires that bridge before any frontend work assumes the endpoints exist.

> **Phase 4 alignment:** the backend now has a **model bootstrap startup gate** (04-03) — it refuses to start on incomplete models, so every TestClient test below enters a lifespan that verifies the model set. The gate runs against the default models dir (`model_assets_owned`, the complete owned copy) or `MODELS_DIR`. Backend tests run on the **`.venv-clean` combined interpreter** (the Phase 4 runtime that carries fastapi/aiosqlite/httpx). To keep the gate fast in tests and avoid a full 12 GB hash on a markerless checkout, the test fixture should set `MODELS_VERIFY_MODE=fast` (presence check only) — the gate still fails on genuinely missing models, but does not re-hash the whole set every run.

Output: A wired FastAPI router (backend/api/settings.py) mounted in backend/main.py, an httpx dev-dependency so FastAPI TestClient tests can run, and a contract test file proving the three GET endpoints answer correctly against a temp SQLite database.

    2. GET /api/projects/{project_id}/settings — depend on backend.api.deps.get_project (validates the 32-hex id -> 400, existence -> 404), then run a synchronous block in asyncio.to_thread: open sqlite3.connect(str(get_settings().db_path)), set PRAGMA foreign_keys=ON, call the readiness helper (see below), read store.resolve_all(conn, project_id=project_id), close, return {"values": <result>}. This is what makes the API self-sufficient regardless of whether Phase 4 already applied the settings DDL or seeded presets (do not assume its internals).

    The sync-bridge helper: one context-manager that connects to get_settings().db_path, yields the connection, and closes it; handlers call store/presets functions inside asyncio.to_thread with a fresh connection per request. Do not reuse the aiosqlite Database singleton for store calls — it is a different driver.
