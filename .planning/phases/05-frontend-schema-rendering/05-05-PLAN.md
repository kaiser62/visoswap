<interfaces>
Source semantics to port (visoswap/settings/gates.py — read it in full before writing gates.ts; it is the authoritative behaviour, including the two counterintuitive rules):
- mechanism "toggle": the gate is satisfied when the combined checked state of the deciding parents equals required_value (a boolean). Rule "single": one parent. Rule "all" (upstream spells it 'A|B'): AND — starts true, any unchecked parent clears it. Rule "last" (upstream 'A, B'): only the FINAL parent decides.
- mechanism "selection": satisfied when the single parent's current value equals required_value exactly (string equality).
- deciding parents = gate.parents for every rule except "last", where only the last parent decides.
- Transitive: a key is enabled only when its own gate is satisfied AND every deciding parent is itself enabled (gates.py's transitive visibility, the one deliberate divergence from upstream).
- values is the full resolved map (all 201 keys present — resolve_all guarantees this in the backend; the frontend's values state holds all 201).

SchemaControl (plan 03) currently renders every control enabled. This plan adds: disabled prop -> control rendered disabled with a lock hint (e.g. a lock glyph + title "Locked: enable {deciding parent label}") — the control stays in the DOM and the count of rendered controls is unchanged (FRONTEND-01 criterion 1 counts rendered controls, disabled or not).

Frontend test pattern (established in plans 03-04): vitest + jsdom, explicit imports from 'vitest', stubbed global fetch, real schema.json fixture from ../../visoswap/schema/schema.json.
</interfaces>
