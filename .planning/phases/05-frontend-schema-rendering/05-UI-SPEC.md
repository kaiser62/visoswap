## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline gaps inside control rows |
| sm | 8px | Compact element spacing, control-to-label gap, chip padding |
| md | 16px | Default element spacing, control row padding, card padding |
| lg | 24px | Section padding, group card padding, modal padding |
| xl | 32px | Layout gaps, sidebar-to-content gap, modal inner gaps |
| 2xl | 48px | Major section breaks, page top padding |
| 3xl | 64px | Page-level spacing, header height allowance |

Exceptions: none. All interactive control heights are 32px (`h-8`) — a multiple of 4 and a comfortable target for a dense 201-control settings surface.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 16px | 600 | 1.2 |
| Display | 20px | 600 | 1.2 |

3 sizes (14 / 16 / 20), 2 weights (400 / 600). 14px body suits a dense settings surface; control labels are semibold so the 201 labels stay scannable next to their controls; help text reuses Body at the secondary text color; the app title is Display and group/section headings are Heading.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FAFAFA` (neutral-50) | App background, page surfaces behind cards |
| Secondary (30%) | `#FFFFFF` (white) | Cards, sidebar, nav, control rows, modals |
| Accent (10%) | `#2563EB` (blue-600) | Active sidebar item, primary Save Changes button, dirty-change markers, focus rings, active preset selector state |
| Destructive | `#DC2626` (red-600) | Destructive actions only: discard-changes confirmation, reset-to-default |

Supporting neutrals (outside the 60/30/10 split — text, borders, hover only): text primary `#171717` (neutral-900), text secondary/help `#737373` (neutral-500), text disabled `#A3A3A3` (neutral-400), borders/dividers `#E5E5E5` (neutral-200), surface hover `#F5F5F5` (neutral-100).

**Accent reserved for:** active sidebar item indicator, primary "Save Changes" button, dirty-change markers (dot + "Modified" chip), keyboard focus rings, active preset selector state. Never used for: control labels, help text, borders, disabled states, or bulk background fills.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **Save Changes** — header button, enabled only when ≥1 control is dirty; persists only changed values (D-02) |
| Empty state heading | **No settings available** |
| Empty state body | The schema returned no controls. Check that the backend is running and serving `/api/schema`, then reload. |
| Error state | **Couldn't load settings** — the backend didn't respond. Check that the server is running, then retry. (banner + Retry button re-fetches schema and settings) |
| Save failure state | **Couldn't save your changes.** They're still in the editor — check the backend and try again. |
| Destructive confirmation | **Discard changes:** This discards N unsaved change(s). This can't be undone. `[Cancel]` `[Discard]` |

Preset apply confirmation (non-destructive, D-04): modal titled **Apply preset {name}** listing the diff — "Changes N setting(s) to this preset's values" (noting any that differ from unsaved edits) — with `[Cancel]` `[Apply]`. Nothing persists until the user confirms Apply.

> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 10 covered, 1 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | settings-list | ✅ covered | A schema with zero controls renders the documented "No settings available" copy; the backend guarantees ≥1 control, so this is defensive |
| loading | settings-list | ✅ covered | First paint shows skeleton group sections while `GET /api/schema` + settings resolve; sidebar shows section shells; controls render once values arrive |
| error | settings-list | ✅ covered | Fetch failure renders the documented "Couldn't load settings" banner with Retry; no controls render until data resolves |
| populated | settings-list | ✅ covered | All 201 controls render, grouped tier → logical group, in schema order within a group; sidebar mirrors the same hierarchy (D-01) |
| partial | settings-list | ✅ covered | Only changed controls are dirty; the header Save button shows the count ("Save Changes (N)") and is disabled at zero; edited vs inherited values are never conflated (D-02) |
| partial | interactive-control | ✅ covered | Gated controls (144 of 201 carry a schema `gate`) render disabled with a lock hint while the parent toggle is off; enabling the parent re-enables them per the gate rule |
| overflow | settings-list + nav | ✅ covered | Sidebar scrolls independently (`overflow-y-auto`, fixed height); the 57-control Face Mask group scrolls within the main panel; no page-level clipping |
| zero-one-many | presets | ✅ covered | Zero presets → selector shows "No presets" and apply is disabled; the 2 seeded presets (`A`, `with AUD`) list as options; any count renders the same selector (D-04) |
| long-text | static-content | 🧪 backstop | { statement: "Control `help` text wraps within its row (max 2 lines) and never overflows the panel; full text remains available via title tooltip", verification: backstop } |
| error | preset-apply | ✅ covered | Apply failure keeps the modal open, shows the documented error, and writes nothing — the apply PUT is atomic per preset |
| error | save | ✅ covered | Save failure keeps the dirty state intact and shows the documented "Couldn't save your changes" message with a retry path |
