<decisions_made>

- The overlay writes the DOM attribute in the frame callback and *keeps* the
  state update, so the React commit that follows is a no-op. Removing the state
  update would desynchronize the component from what is on screen.
- Each worker owns its own generator and engine, so only one thread is ever
  inside a given one — which is what makes `asyncio.to_thread` safe there.
- A forced stop returns without awaiting and reaps in the background, then
  settles abandoned `processing` rows as cancelled. An unsettled row pins the
  recording watermark under it forever.
- `drain_to` now *waits for* a pump already released by `finish()` rather than
  bounding it. The stop derives its bound from the last generated timestamp,
  which on a range run is well behind where the full drain has reached.
- The pump finalizes itself on end-of-source, and `aclose` holds a lock for the
  whole finalization so the stop that follows waits rather than racing the
  promote and export.
- The launcher serves everything from uvicorn on one port rather than running
  vite: the vite dev proxy covers `/api` only, not `/ws`.
</decisions_made>

## Critical Anti-Patterns (do NOT repeat these)

- [ANTI-PATTERN]: `asyncio.wait_for(scheduler.stop(), timeout=…)` against a
  wedged worker → it hangs, because cancelling `stop()` requires the
  cancellation to travel through the very worker that is ignoring it. Use
  `asyncio.wait({task}, timeout=…)` and watch the task instead.
- [ANTI-PATTERN]: a test task that ignores `CancelledError` unconditionally →
  it outlives the event loop and hangs the whole pytest process (this cost two
  `Stop-Process` kills). Always give it an `asyncio.Event` escape hatch.
- [ANTI-PATTERN]: `@pytest.fixture async def …` under pytest-asyncio strict mode
  → the test receives a generator. Use a sync fixture plus an
  `@asynccontextmanager` opened inside the test.
- [ANTI-PATTERN]: guarding `aclose` with a bare `if self._closed: return` while
  something else can call it concurrently → the second caller returns while the
  file is still being promoted and copied, and Windows raises `PermissionError`
  on the `.part`. Hold a lock across the whole finalization.
- [ANTI-PATTERN]: attributing a latency measurement to the code path under test
  without a control measurement. The first forced-stop timing (1383ms) was
  event-loop starvation, not the force path (13–60ms).
