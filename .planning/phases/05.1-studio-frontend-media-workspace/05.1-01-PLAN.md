<objective>
Remove the per-frame source re-embed tax from the engine seam and prove the removal with
a real measurement, then prove the seam is safe to change faces on.

This is the phase tracer. It is the thinnest slice that runs the whole vertical the rest of
Phase 05.1 sits on: `Engine.swap` -> `EngineFrameGenerator.generate_at` -> the generation
worker -> frame rows and frame files -> `GET /api/projects/{id}/frame-at`. Nothing else in
this phase may land until this slice is measured, because `docs/benchmark-baseline.md`
records the standing decision: *"No overlay implementation may land against today's numbers."*

Purpose: `Engine.swap` (visoswap/engine.py L387) opens every single frame with
`source_store = self._source_embedding_store(source_path)`, which re-runs `run_detect` plus
`run_recognize_direct` under all four `RECOGNITION_MODELS` on an image that never changes
between frames. Measured cost of that tax on an idle GPU: 147.65 ms/frame vs 96.85 ms/frame
with the source embedded once — 52% throughput, for a value that is constant per file.

Output: a private memo inside `Engine`, a sealed-runner mode that proves its identity and
invalidation semantics, a benchmark gate mode that refuses to report from a contended GPU,
an end-to-end hot-swap purity test, and a `docs/benchmark-baseline.md` section carrying the
real post-cache number rather than the projection.
</objective>

| Boundary | Description |
|----------|-------------|

| benchmark tool -> filesystem/GPU | `tools/benchmark_engine.py` runs on the sealed interpreter with model weights reachable. |
| `scheduler/start` -> project frame cache and recorder output | The per-start wipe deletes files under the project directory. |

| T-05.1-01-01 | Tampering | `Engine._source_embedding_store` cache key | high | mitigate | Key includes `st_mtime_ns` and `st_size` from a stat taken on every call, so an in-place file replacement cannot be served from the memo. Asserted by the `rewrite` probe. |

| T-05.1-01-03 | Information disclosure | benchmark and runner report lines | medium | mitigate | Report lines carry timings, shapes, counts and booleans only — no pixel data and no embedding values (T-02-10, already the rule in `tools/benchmark_engine.py`'s docstring). |
| T-05.1-01-04 | Denial of service | unbounded memo growth | low | accept | One entry per distinct source file per `Engine` bind, and `load` clears it. The `entries` probe reports the count so growth is visible; a project uses one face at a time. |
