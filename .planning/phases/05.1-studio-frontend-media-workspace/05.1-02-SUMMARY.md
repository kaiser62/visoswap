# Phase 05.1 Plan 02: Global Face Library Backend Summary

**Machine-global content-addressed face store behind /api/faces with 112px thumbnails, project face activation returning an assignment-list contract, and warn-and-cascade deletion that names its victims before removing anything.**

## Accomplishments
- `backend/services/facestore.py`: one machine-global store at `data_dir/faces` (outside `projects_dir`), identity = blake2b-16 of the bytes, so the same image uploaded twice is one library entry and every on-disk name is derived (`{digest}{ext}` + `{digest}.thumb.jpg`) rather than accepted.
- `/api/faces`: streaming upload copied from `projects.upload_source` (size-capped, `.part` cleaned up on every failure arm, `OSError`→507), newest-first listing, full image + 112x112 thumbnail served with immutable `Cache-Control`; thumbnails are never-fatal (warn + null URL).
- `POST /api/projects/{id}/face` binds a library face server-side and returns `{"assignments": [{target_index: 0, face_id, thumbnail_url}]}` — the singular-request/plural-response seam D-04 planned; `_public` now emits `source_face_id`, never a path.
- D-05 deletion honesty: `GET /api/faces/{id}/usage` feeds the confirm dialog, unforced delete answers a machine-readable 409 listing affected projects, `?force=true` stops running schedulers, nulls rows **before** unlinking, and a faceless project's scheduler start is refused with a clear 400.

## Decisions Made
- Removed `source_face_path` from `ProjectUpdate`. The threat register asserted "`ProjectUpdate` continues to refuse it from the client," but the field was actually PATCH-writable — plan 01's purity E2E reached it exactly that way. Server-assigned-only is now true, and the purity test drives the same stop→swap→start cycle through the product surface.
- Activation request/response shape follows the plan's assumption-delta decision verbatim: singular request, assignment-list response.
- Listing `display_name` falls back to the face id (see deviation 2): the two-files-per-face invariant forbids sidecar metadata, and adding a faces DB table would be an architectural change beyond the plan.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Enforced server-assigned-only for `source_face_path`**
- **Found during:** Task 2 (schemas/_public work)
- **Issue:** `ProjectUpdate` carried `source_face_path: str | None` despite the comment "Server-assigned only", letting any client PATCH an arbitrary filesystem path onto a project row (T-05.1-02-07 mitigation was factually unmet).
- **Fix:** Removed the field from `ProjectUpdate` (DB allowed-set keeps it for server writes); migrated `tests/test_hot_swap_purity.py`'s two PATCH bindings to upload + activate through the new API, keeping the whole stop→change-face→start cycle end-to-end through real routes.
- **Files modified:** backend/api/schemas.py, tests/test_hot_swap_purity.py
- **Verification:** tests/test_hot_swap_purity.py 2 passed after migration
- **Committed in:** 749c3a6 (Task 2 commit)

**2. [Rule 3 - Blocking constraint] Listing display_name falls back to the face id**
- **Found during:** Task 1 (list_faces implementation)
- **Issue:** The plan asks list records to carry "display_name (the sanitized original filename)", but also mandates storing leaves exactly two directory entries — no sidecar may persist the name, and a faces DB table is out of the plan's artifact set (architectural).
- **Fix:** store() returns the sanitized original name in its immediate record; list_faces derives a stable display name from the content id. Original-name persistence is deferred to plan 06 if the UI needs labels (thumbnails are primary there).
- **Files modified:** backend/services/facestore.py
- **Verification:** service-level listing tests pass; dedupe/count criterion holds
- **Committed in:** 7826f5b (Task 1 commit)

**3. [Rule 1 - Test bug] Fixture images were not decodable images**
- **Found during:** Task 1 GREEN (thumbnail warnings, 2 failures)
- **Issue:** Handcrafted fake PNG header bytes can't be decoded by PIL, so thumbnails legitimately never materialized.
- **Fix:** Test fixtures build real PNG bytes via PIL; production code unchanged.
- **Committed in:** 7826f5b (Task 1 commit)
