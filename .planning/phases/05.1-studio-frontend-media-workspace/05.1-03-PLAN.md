<objective>
Complete the backend the media workspace needs: a preview that costs one frame, a take that
survives every stop, and a way to list what has been made.

Purpose: three user-visible promises have no server behind them. D-09's Preview Current Frame
needs a path that renders one frame without the scheduler — today the only way to get a swapped
frame is to start a run. D-12's save-on-stop takes need the predecessor's `_stem` semantics,
which this repo's `Recorder._export` does not have: it names the export from the project name
alone, so two runs of one project collide into `name.mp4` and `name (2).mp4` and nothing says
which face or when. D-10's Gallery page needs the output folder to be listable.

Output: a preview router with its own storage location, a recorder export that names a take by
project, timestamp and face, and a takes router that serves the output folder with Range support.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `POST /api/projects/{id}/preview` | An untrusted timestamp triggers GPU work outside the scheduler's admission control. |
| browser -> `GET/DELETE /api/takes/{name}` | An untrusted string names a file in a folder that sits outside `data/projects`. |
| `Recorder.face` / `Recorder.name` -> output filename | Project and face names chosen by the user become components of a filesystem name. |
| output folder -> browser | Every take the user has ever made is served from one directory. |
