## Accomplishments
- `frontend/src/index.css` `@theme` now carries the ten webui2 palette values (`--bg`…`--bad`) under the `--color-*` namespace — Tailwind v4 generates `bg-card`, `border-line`, `text-muted`, `bg-active` etc. for the whole app — plus a `@layer base` block setting `color-scheme: dark` so the ~201 native form controls paint dark.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking criterion] Acceptance grep counted a doc-comment mention of `data-control-type`**
- **Found during:** Task 2 (acceptance gate run)
- **Issue:** Criterion requires `grep -c "data-control-type" SchemaControl.tsx` to report 1, but the module docstring also named the attribute verbatim (pre-existing), making the count 2 even though the code sets it exactly once, on the shared `ctl` object.
- **Fix:** Reworded the doc comment ("carries `data-key` plus its type marker via one shared attribute object") so the gate measures the real invariant. No behavior or test change; the render-count source-scan test is unaffected.
- **Files modified:** frontend/src/components/SchemaControl.tsx (docstring only)
- **Verification:** grep now reports 1; full suite still green
- **Committed in:** 9618cc0 (Task 2 commit)

**2. [Rule 3 - Blocking] Playwright webServer could not spawn its backend command**
- **Found during:** Task 3 verification (`npm --prefix frontend run test:e2e`)
- **Issue:** `playwright.config.ts` spawns `..\.venv-clean\Scripts\python.exe ...` with `cwd: '..'`; on this Windows setup the relative path resolved wrong and the webServer died with "The system cannot find the path specified." before any test ran.
- **Fix:** Started the identical backend myself (`.venv-clean\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000`, repo root) as a managed background job, confirmed `/api/health` 200, and let `reuseExistingServer: true` attach Playwright to it. Config file intentionally left unmodified (out of task scope; noting for the verifier — an absolute-path or `%CD%`-independent command would make the config self-sufficient).
- **Files modified:** none (runtime workaround only; server killed after E2E)
- **Verification:** `test:e2e` → 5 passed against the real backend driving the rewritten shell
- **Committed in:** n/a (no repo change)
