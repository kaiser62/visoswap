# Phase 05.1 Plan 06: Media card, face library UI, generation modes and auto-preview Summary

**The workspace can now take a video, pick a face from the shared library, choose how frames are generated, and see a swapped frame on demand — without any of it ever competing with playback.**

## Performance

- **Duration:** ~40 min (recovery of an interrupted run plus completion)
- **Tasks:** 3
- **Files modified:** 14 (8 created, 6 modified)

## Accomplishments
- `MediaCard.tsx`: file picker and URL form, an 8 GB client-side refusal that issues zero requests, verbatim 413 surfacing, in-flight disabling with progress, and replacement in place.
- `FaceLibrary.tsx`: project-id-free list request (D-03), upload with content-addressed dedupe, active mark driven by the open project's payload, and a delete affordance per face.
- `FaceDeleteDialog.tsx`: usage is read before any confirm control exists; affected projects are named; `force` is sent only when usage says something points at the face (D-05).
- `ModeSelector.tsx`: the three D-07 modes with Stream-Live default; the interval field appears only in Interval mode and persists through the project row.
- `PreviewControls.tsx`: manual preview plus an auto-preview that is off by default, collapses a slider drag into one request at rest, and re-reads its gates at fire time.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Test harnesses built a fetch mock and never installed it**
- **Found during:** Tasks 1 and 2 (recovered tree)
- **Issue:** `media-card.test.tsx` called `await mounted()` with no argument (`TypeError: Cannot read properties of undefined (reading 'mock')`), and `face-library.test.tsx`'s `installFetch` never called `vi.stubGlobal`, so requests reached the real `fetch` (`Failed to parse URL from /api/faces`).
- **Fix:** Pass the mock at both call sites; install the stub inside `installFetch`; make `mountedWithDialog` take the caller's mock rather than orphaning it with a second install.
- **Committed in:** `cbe7701`, `86c1ddb`

**2. [Rule 1 - Bug] The face stub answered uploads without storing them**
- **Found during:** Task 2
- **Issue:** The upload response returned a face the subsequent list request did not contain, so "uploading adds an entry" and "the same image twice stays one entry" both asserted against a list that never changed. Entry counting also matched `face-delete-*` testids, double-counting every face.
- **Fix:** The stub appends the uploaded face if absent (content addressing modelled by a fixed resolved id), the active face is per project rather than pinned by an override, and entry counting excludes delete affordances.
- **Committed in:** `86c1ddb`

**3. [Rule 1 - Bug] The start body lost its explicit flags in the range branch**
- **Found during:** Task 3
- **Issue:** `media-context.test.tsx` (pre-existing, plan-protected from modification) failed: the ranged start body carried only `range_start`/`range_duration`, dropping `full_video: false` and `current_time`.
- **Fix:** Corrected `MediaContext.startRun` rather than the test, restoring the body shape plan 05 pinned for every mode.
- **Committed in:** `7d03034`

**4. [Rule 2 - Wrong artifact] `preview-modes.test.tsx` was not a test**
- **Found during:** Task 3
- **Issue:** The recovered file used CommonJS `require('../state/MediaContext')` inside an ESM vitest module (7 failures, `Cannot find module`), mocked both context hooks so no shipped code ran, imported a non-existent `api` object, and contained self-admitted non-assertions ("we assume the logic is correct", `expect(true).toBe(true)`). None of the plan's acceptance criteria — zero preview requests while playing for both triggers, one request after ten changes and an advanced timer — were checked.
- **Fix:** Rewritten as 14 tests against the real `MediaProvider` with a stubbed global fetch, the settings surface injected through the exported context, and fake timers for the debounce, covering every Task 3 behavior bullet including both playing-video triggers and the mid-window play cancellation.
- **Committed in:** `7d03034`

**5. [Rule 3 - Blocking] Four typecheck errors blocked the build gate**
- **Found during:** Gates
- **Issue:** `tsc -b` failed: `FaceUsageProject` was imported from `../lib/api` but never re-exported there (two components), `initialUsage` was declared and never read in the dialog, and one `face-library.test.tsx` call site passed no arguments.
- **Fix:** Re-exported the type from `api.ts`; the dialog now seeds its body from the strip's prefetch and drops the seed when the face id changes; fixed the call site.
- **Committed in:** `86c1ddb`, `7d03034`
