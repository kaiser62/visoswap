<objective>
Tell the user what actually happened.

Purpose: the benchmark evidence for this phase says live parity at 1080p24 is not promised
— the measured floor after the embedding cache is around ten frames per second at 1080p, and
the overlay policy is nearest-previous. That is a legitimate product as long as the interface
is honest about it. An overlay that silently repeats the same swapped frame for four video
frames looks broken; the same overlay next to a panel reading "swapped 41% of the frames you
watched, generating at 10.3 per second against a 24 per second video" reads as a cadence the
user understands and can act on by lowering the processing scale or exporting instead of
streaming.

The same honesty applies to output. The recorder's partial file is a valid playable mp4 at
every instant and the status endpoint already distinguishes it from a finished one, so the
Results card can offer the recording mid-run — provided it says which one it is offering.

Output: a Jobs card built on a measurement the player actually takes, a Results card driven
by the completion flag the backend already reports, and a Gallery over the takes API from
plan 03.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `GET /api/takes` -> rendered take names | Server-derived filenames reach the DOM and become link targets. |
| take name -> `GET`/`DELETE /api/takes/{name}` | A name from a list becomes a path segment on a request. |
| status poll -> Results card | A repeating client-driven request while a run is under way. |
| delete affordance -> `DELETE /api/takes/{name}` | A destructive action on the user's exported work. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05.1-07-01 | Tampering | take name used in a request path | high | mitigate | The client only ever sends a name it received from the list response and encodes it as a single path component; the server re-validates it against the derived-name rule and the containment check built in plan 03. Validation is the server's, not the client's. |
| T-05.1-07-02 | Tampering | take name rendered in the list | medium | mitigate | Rendered as a React child; the raw-HTML prop is absent from the whole frontend and asserted absent by plan 04. |
| T-05.1-07-03 | Denial of service | status polling outliving a run | medium | mitigate | The interval is created only while a run is active, cleared when it ends and cleared on unmount; asserted with fake timers. |
| T-05.1-07-04 | Denial of service | the gallery view unmounting gated controls | high | mitigate | Both views stay mounted and the inactive one is hidden with CSS; the control count is asserted across the toggle. |
| T-05.1-07-05 | Repudiation | a partial recording presented as finished | high | mitigate | The label is driven by the backend's completion flag, never by the running flag; asserted across a flag flip. |
| T-05.1-07-06 | Repudiation | an unmeasured coverage figure presented as fact | high | mitigate | The cadence block renders an explicit not-yet-measured state until samples exist, and always shows the raw counts behind the percentage. |
| T-05.1-07-07 | Tampering | accidental take deletion | medium | mitigate | The delete goes through the shared confirmation dialog; takes are the user's accumulated work and D-12 makes accumulation the point. |
| T-05.1-07-08 | Information disclosure | take names revealing project and face names | low | accept | Single-user local application (REQUIREMENTS.md "Out of Scope": multi-user, auth, hosting); the naming is the D-12 requirement and the names are the user's own. |
