# Phase 05.1 Plan 07: Jobs, results and gallery Summary

**The interface now reports the cadence it measured rather than the cadence it hopes for, offers the recording while it is still growing without ever calling it finished, and lets the user browse every take without unmounting a single control.**

## Performance

- **Duration:** ~50 min
- **Tasks:** 3
- **Files modified:** 9 (5 created, 4 modified)

## Accomplishments

- `JobsCard.tsx`: queue counts fed entirely by `queue_updated`, an in-flight list built from `generation_started`/`completed`/`failed`, the measured coverage block, the generation rate beside the video frame rate, the nearest-previous policy line, and a retry that only exists when `failed > 0`.
- `MediaContext.tsx`: a `coverage` pair of integers and an `inFlight` list, with the tally reset on any transition into running so a ratio describes one run.
- `PlayerCard.tsx`: one added `recordCoverage(entry !== null)` call using the result the handler already had — no second index lookup and nothing awaited, so the overlay invariant holds unchanged.
- `ResultsCard.tsx`: labels from the backend `complete` flag, polls the status endpoint only while a run is active, keeps the last known size with a stale marker when a poll fails, and offers download plus inline playback straight from the output endpoint.
- `GalleryView.tsx`: newest-first takes with size, modified time and partial markers, inline playback, per-take download, and delete behind a confirmation.
- `App.tsx`: a page-level view toggle rendering both views with the inactive one hidden, so the 201 gated controls stay mounted while the user looks at takes.

## Key Decisions

1. **Coverage stores two integers, not a percentage.** `lookups === 0` is then a representable state, which is what makes "not yet measured" honest instead of a rendered 0%.
2. **The reset lives in the reducer's running transition**, not in the start thunk, so a run started from anywhere — button, socket event or status poll — resets the tally identically.
3. **The results card polls with its own request rather than the context's `refreshStatus`**, because that thunk deliberately swallows failures; a card that must show staleness needs to see the rejection.
4. **The view toggle hides with the `hidden` attribute plus a Tailwind class**, not a class alone: `display: contents` on the studio wrapper would otherwise defeat a class-only hide, and the attribute keeps the behavior identical under jsdom.
5. **The gallery's retry is labelled "Retry loading takes"**, because a bare "Retry" collides with the settings error banner's control in a full-App render.

## Deviations

- **Rule 2 (auto-fixed, in-scope):** `Badge` does not forward arbitrary props, so the results label testid moved to a wrapping span rather than changing the shared primitive.
- **Rule 2 (auto-fixed, in-scope):** the recording poll interval was set to 2 s. The first draft's 1 s cadence fired twice per test tick, which let a successful poll immediately clear a staleness the test had just induced — the shorter interval was hiding a real ordering, not the test being wrong.
