<objective>
Finish the ladder rung the evidence file left open, and prove the phase against the real
thing.

Purpose: `processing_scale` and `processing_width` are columns on the project, fields on
both request models, and a helper in the generation worker — and on the engine backend they
do nothing at all. The worker applies them while extracting a source frame, and the engine
generator never extracts a source frame: it holds the video open and decodes internally.
Every project in this product uses the engine backend. The knob has been inert since it was
added, which is worse than absent, because the interface is about to expose it.

The benchmark file already names this rung as unmeasured and requires its own gate. That
ordering is the whole point: the thread slider looked like a lever until it was measured,
and D-14 now forbids advertising it. This rung gets the same treatment — implement, measure
on an idle card, and let the recorded number write the label.

Output: a scale that reaches the engine without widening its public surface, a benchmark
mode that refuses to report from a contended card, a control whose description comes from
the measurement, an end-to-end spec covering the workspace, and a human verification of the
phase.
</objective>

    - Swapping with a target width smaller than the native width returns a frame whose dimensions still equal the native dimensions.
    - Swapping with a target width smaller than the native width performs its detection and swap work at the smaller width — observable as a lower measured duration on the same frame.
    - A target width at or above the native width is ignored rather than upscaling.
    - A target width is coerced to an even number, because odd dimensions break downstream encoders.

  <action>
    Add an optional target-width keyword to the engine's swap entry point, defaulting to none.
    A keyword argument does not add a public name, so the pinned three-method surface is
    untouched — confirm this against the surface test before implementing, and stop if that
    test pins signatures rather than names.

    Apply the resize at the frame boundary and nowhere else: immediately after the frame is
    decoded, resize down to the target width preserving aspect ratio and forcing even
    dimensions; immediately before returning, resize the result back to the media's native
    dimensions. Both ends matter. The downscale is where the saving is — detection, landmark
    work, paste-back and the colour pipeline all run on the smaller frame. The upscale is what
    keeps the contract every downstream consumer already relies on: the recorder composes
    generated frames onto the original timeline and the overlay positions an image over a video
    element, and both break on a frame that changed size mid-run.

    Never upscale on the way in. A target at or above the native width is ignored, mirroring the
    existing worker helper's rule so the two paths cannot disagree about what the same project
    row means.

    In `backend/services/engine_backend.py`, resolve the project's target width the same way the
    worker helper does — an explicit width wins, otherwise a scale below one applied to the
    media's width, otherwise nothing — and pass it into the swap call from `generate_at`.
    Import or reuse the worker's helper rather than restating the rule; two copies of a
    downscale policy is how the preview and the run start disagreeing.

    Leave the safe-provider tuple, the module docstring's refusal rationale, the provider check
    and the generator's validate branch exactly as they are. D-15c keeps TensorRT refused, and
    the reason is unchanged by this rung: the refusal is about a relative cache path, not about
    speed.

    Add a scale mode to `tests/_engine_runner.py` following plan 01's mode, dispatched from
    argv, reporting per-scale timings and output dimensions in the existing report-line format.
    Report timings, shapes and counts only — no pixel data and no embedding values, per T-02-10.

    Create `tests/test_engine_scale.py` driving that mode through the sealed runner, covering
    the behavior block. Nothing in it skips.
  </action>
