## Pattern Assignments

### `backend/api/faces.py` (route, file-I/O + CRUD)

**Analog:** `backend/api/projects.py` — copy the upload boundary wholesale.

**Upload boundary pattern** (projects.py L88–125): validate name → size-capped chunked stream to `.part` → atomic replace → bind/probe → strip paths on return:

```python
safe_name = video.validate_upload_name(file.filename or "video.mp4")   # 400 on VideoSourceError
cache.ensure_project_dirs(project_id)
dest = cache.source_dir(project_id) / safe_name
cache.assert_within_project(dest, project_id)
written = 0
tmp = dest.with_suffix(dest.suffix + ".part")
with tmp.open("wb") as handle:
    while chunk := await file.read(CHUNK):
        written += len(chunk)
        if written > settings.max_upload_bytes:
            raise HTTPException(status_code=413, detail="file too large")
        handle.write(chunk)
tmp.replace(dest)          # except OSError -> 507, unlink tmp in both failure arms
```

**Response-shaping pattern** (projects.py L182–195 `_public`): never leak absolute paths to the browser — pop `video_path`/`source_face_path`, expose booleans + relative URLs. The face library list payload must do the same (serve thumbnails via `/api/faces/{id}/thumb`, never disk paths). Activation writes `source_face_path` per project — note schemas.py L39–41 marks that column "server-assigned only"; the activate endpoint updates it server-side exactly like `_bind_source` does.

**Delete-with-references pattern** (projects.py L78–85): stop dependent work first, then delete rows, then `rmtree`. For D-05 warn+cascade: list affected projects in the response of a dry-run/`?confirm=` style call, then on confirm delete file + null each project's `source_face_path` back to the no-source state.

### `backend/services/recorder.py` — D-12 save-on-stop port (service, streaming)

**Analog:** `D:/Dev/visomaster_live/backend/services/recorder.py` L389–435 — the delta vs this repo is small because the current recorder (L62–97, L356–397) already has `_free_path`, `_promote`, `_export`, `output_include_partial`. Port the timestamped stem verbatim:

```python
def _stem(self) -> str:
    """`project_datetime_face`, each part sanitized and empties dropped."""
    def part(value: str) -> str:
        cleaned = cache.sanitize_filename(value, "").rsplit(".", 1)[0]
        return cleaned.strip("._")
    stamp = datetime.now().strftime("%Y%m%d-%H%M%S")
    pieces = [part(self.name), stamp, part(self.face)]
    return "_".join(p for p in pieces if p) or stamp
```

Required deviations: (1) current `_export` builds `f"{stem}{suffix}"` from project name only (L389–390) — swap to `{self._stem()}{suffix}`; (2) `Recorder.__init__` needs a `face: str = ""` kwarg fed by `scheduler._start_recorder` from the project's active face; (3) exports already accumulate correctly — `clear_output` (L85–97) wipes only the working `output.mp4(.part)` at start, never `output_dir`; (4) export stays inside `aclose()`'s try/except — already never-fatal. Keep `.partial` suffix logic identical (L420–424).

### One-shot preview endpoint (route, request-response)

**Analog:** `backend/api/playback.py::frame_at` (L211–232) for the resolve-and-serve shape, plus `generation.py::start_scheduler` (L34–40) for fail-fast validation *without* starting anything:

```python
target = target_for_rate(t, grid_rate(project))       # nearest-previous, never future
row = await db.get_frame(project["id"], target)
if row is None or row["status"] != STATUS_COMPLETED:
    return {"timestamp": target, "available": False, "url": None}
```

Preview differs: it must render on demand even when nothing was generated yet. Build a throwaway generator like start_scheduler's probe (`build_generator(project, 0.0)` → `await generator.validate()` → always `close()`), generate one frame at the playhead timestamp into the generated dir, return the same `{timestamp, available, url}` envelope so the UI reuses `frame/{key}` serving. Never touch `registry`/scheduler state.

## Shared Patterns

### Path-safety + upload boundary
**Source:** `backend/services/cache.py` (`validate_project_id` L23–27, `sanitize_filename` L30–41, `assert_within_project` L101–107), `projects.py` upload excerpt above.
**Apply to:** every new file-touching route (faces upload/delete, gallery download, preview). User strings never become path segments; sanitize → derive → contain-check.

### HTTP error mapping
**Source:** `backend/api/settings.py::_settings_error` L36–49 (caller mistake → 400 with message; infra fault → 500) and `deps.py::get_project` (400 invalid id / 404 missing).
**Apply to:** all new routers; raise `HTTPException` with `detail`, never leak tracebacks.

### Recorder/export resilience
**Source:** `recorder.py` docstring invariants + `_export` never-fatal try/except.
**Apply to:** D-12 port and Final Results card — export failures log a warning and never fail the run; UI treats `.part`+`X-Recording-Complete: 0` as a live recording.

### Informational-realtime contract
**Source:** `ws.py` module docstring + reconnect-refetch behavior.
**Apply to:** ws hook, overlay renderer, Jobs tab — tolerate socket drops identically; state reconciles from REST (`/frames`, `/generation/status`) on reconnect.

### All controls rendered (count gate)
**Source:** `render-count.test.tsx` + `App.tsx` flat-group render (L134–145).
**Apply to:** any tabbing/collapsing of the Controls card — hide with CSS, never unmount `[data-key]` nodes.
